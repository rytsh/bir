# Browser translation integration compatibility — checked 17 November 2026

## 1. Which models can actually integrate with the current app?

### Takeaway
Keep M2M100 as the low-risk, permissively licensed fallback. For a genuinely newer quality-focused browser option, investigate Hy-MT2 1.8B first, but treat its fresh community Transformers.js exports as experimental; HY-MT1.5 has a clearer established onnx-community integration example. TranslateGemma 4B has an actual browser implementation but a much larger download. NLLB is the simplest pipeline-compatible alternative, not an unrestricted production replacement.

### Cited Findings
- Current component has only `Xenova/m2m100_418M`, types the instance as `TranslationPipeline`, invokes `pipeline("translation", selectedModel)` without explicit device/dtype, supplies `src_lang`/`tgt_lang`, and reads `translation_text`. Languages use M2M codes such as `en`, `tr`, `zh`; no chunking or output-token cap is present. Model switching overwrites the previous instance without disposal. Installed version verified as **4.3.0**, not merely inferred from dependency range. — [Component](file:///home/ray/repo/bir/src/components/tools/TranslateTool.svelte), [Package](file:///home/ray/repo/bir/node_modules/@huggingface/transformers/package.json).
- Installed 4.3.0 explicitly documents NLLB, M2M100, and mBART translation pipelines. It includes `hunyuan_v1_dense` and `gemma3_text` model support, so these architectures do not inherently require replacing Transformers.js. Architecture support alone does not prove an arbitrary ONNX export works. — [Installed translation pipeline](file:///home/ray/repo/bir/node_modules/@huggingface/transformers/src/pipelines/translation.js), [Installed Hunyuan implementation](file:///home/ray/repo/bir/node_modules/@huggingface/transformers/src/models/hunyuan_v1_dense/modeling_hunyuan_v1_dense.js), [Installed configuration mapping](file:///home/ray/repo/bir/node_modules/@huggingface/transformers/src/configs.js).
- **Newest important candidate: Tencent Hy-MT2-1.8B**, released 21 May 2026, upstream card Apache-2.0. Publisher advertises 33 languages plus variants and explicitly lists Turkish. Its Python example is causal generation, not seq2seq translation. Publisher quality claims are not independent measurements of this app's English↔Turkish use case. — [Upstream model card](https://huggingface.co/tencent/Hy-MT2-1.8B/blob/main/README.md).
- **A Transformers.js-targeted Hy-MT2 ONNX export actually exists:** `konstbet/Hy-MT2-1.8B-ONNX`, uploaded **17 November 2026**, latest checked revision `9d50f9ce17f93215187afb0409e76fd23d241b09`. Card provides `pipeline("text-generation", id, {dtype:"q4f16",device:"webgpu"})`; config supplies external-data and FP16 KV-cache settings. Graph is 369,231 bytes plus 1,074,841,600-byte weight data (~1.075 GB, 1.00 GiB), excluding tokenizer. Author describes a static KV-cache-dimension fix required for JS initialization. This is evidence of deliberate packaging, not independent runtime validation. — [Card](https://huggingface.co/konstbet/Hy-MT2-1.8B-ONNX/blob/main/README.md), [Config](https://huggingface.co/konstbet/Hy-MT2-1.8B-ONNX/blob/main/config.json), [Live file metadata](https://huggingface.co/api/models/konstbet/Hy-MT2-1.8B-ONNX?blobs=true).
- Other MT2 exports exist, including `DavidLuong/Hy-MT2-1.8B-ONNX-q4f16` and `LunarOilRig/Hy-MT2-1.8B-ONNX-q4f16-mirror`; the latter says it is a byte-identical preservation mirror of commit `cb415ae`. Do not report that MT2 has no ONNX/browser candidates. — [HF ONNX model search API](https://huggingface.co/api/models?search=Hy-MT2&filter=onnx&limit=30), [Mirror card](https://huggingface.co/LunarOilRig/Hy-MT2-1.8B-ONNX-q4f16-mirror/blob/main/README.md).
- **Do not equate all ONNX with Transformers.js-ready.** `justinchuby/Hy-MT2-1.8B-ONNX` is packaged for **ONNX Runtime GenAI**, with `genai_config.json` and device-specific folders, despite having a WebGPU variant. Its card documents a tokenizer-regex issue and feeding token IDs via Hugging Face tokenizer. That is not the same drop-in package contract as Transformers.js. Its Hunyuan-license metadata conflicts with upstream MT2's Apache-2.0; check actual licenses before redistributing. — [Export card](https://huggingface.co/justinchuby/Hy-MT2-1.8B-ONNX/blob/main/README.md), [Upstream MT2](https://huggingface.co/tencent/Hy-MT2-1.8B/blob/main/README.md).
- **HY-MT1.5-1.8B:** `onnx-community/HY-MT1.5-1.8B-ONNX` has an explicit Transformers.js example using text-generation, q4 and WebGPU, returning the last assistant message. Quantized q4 graph/data total ~1.406 GB; q4f16 ~1.227 GB. This is a credible smaller browser alternative to TranslateGemma, but older than MT2. Upstream lists 33 languages plus variants, including Turkish, and translation-specific prompts. — [ONNX card](https://huggingface.co/onnx-community/HY-MT1.5-1.8B-ONNX/blob/main/README.md), [File metadata](https://huggingface.co/api/models/onnx-community/HY-MT1.5-1.8B-ONNX?blobs=true), [Upstream](https://huggingface.co/tencent/HY-MT1.5-1.8B/blob/main/README.md).
- **TranslateGemma 4B:** `onnx-community/translategemma-text-4b-it-ONNX` is a real `gemma3_text` export with q4 and q4f16 external-data packages. The `webml-community/TranslateGemma-WebGPU` space source actually calls text-generation on WebGPU with q4, structured translation messages, and assistant-content extraction. Google released the family 15 January 2026; says it evaluated 55 languages and trained on additional pairs, not that all ~500 pairs have confirmed metrics. — [Config](https://huggingface.co/onnx-community/translategemma-text-4b-it-ONNX/blob/main/config.json), [Working browser app source](https://huggingface.co/spaces/webml-community/TranslateGemma-WebGPU/blob/main/src/ai/Translator.ts), [Google announcement](https://blog.google/innovation-and-ai/technology/developers-tools/translategemma/).

### Inferences
- Sensible research shortlist: (1) MT2 1.8B q4f16 experimental WebGPU tier; (2) HY-MT1.5 1.8B q4 as the more established JS-example alternative; (3) TranslateGemma 4B q4 desktop quality tier; (4) NLLB only with explicit noncommercial/research positioning. Preserve M2M for devices lacking usable GPU support.
- Do not promise any candidate is universally better than M2M, especially for EN↔TR, without pair-specific blind comparison. The latest small export's upload date being today makes revision pinning and smoke testing particularly important.

### Gaps
- No model weights downloaded and no real browser generation performed; compatibility classifications are source/config verification, not executed end-to-end certification.
- HY-MT1.5 licensing was not resolved in this pass: upstream README lacks license metadata and `/LICENSE` returned 404. Do not infer Apache-2.0 from MT2 or assign a permissive license without further checking repository license files.
- Google's gated original HF README returned HTTP 401; commercial redistribution terms for TranslateGemma should be checked directly against the applicable Gemma terms before adoption.

## 2. What changes would language handling and pipelines require?

### Takeaway
NLLB needs a language-code adapter but retains the translation call/output contract. Hunyuan and TranslateGemma need a separate causal-generation adapter; changing only the dropdown model ID will not work.

### Cited Findings
- NLLB's documented JS call uses `src_lang:"hin_Deva"` and `tgt_lang:"fra_Latn"`; it returns `translation_text` like the existing app. Appropriate mappings include `en→eng_Latn`, `tr→tur_Latn`, `de→deu_Latn`, `fr→fra_Latn`, `zh→zho_Hans` or `zho_Hant`, `sr→srp_Cyrl`, `no→nob_Latn`, `tl→tgl_Latn`. Script/variant choices mean this is not a trivial universal ISO suffix conversion. — [JS example](https://huggingface.co/Xenova/nllb-200-distilled-600M), [Full language-code list](https://huggingface.co/facebook/nllb-200-distilled-600M/blob/main/README.md).
- Hunyuan's JS usage is `pipeline("text-generation", modelId, {dtype:"q4", device:"webgpu"})`; prompt is a user message instructing translation into a **language name**, e.g. `Turkish`, not `tgt_lang:"tr"`. Extract `output[0].generated_text.at(-1).content`; its published example uses `max_new_tokens:512`, `do_sample:false`. MT2's upstream similarly specifies full names and no default system prompt. — [HY-MT1.5 JS usage](https://huggingface.co/onnx-community/HY-MT1.5-1.8B-ONNX/blob/main/README.md), [MT2 JS usage](https://huggingface.co/konstbet/Hy-MT2-1.8B-ONNX/blob/main/README.md), [MT2 prompt guidance](https://huggingface.co/tencent/Hy-MT2-1.8B/blob/main/README.md).
- TranslateGemma's browser example sends `[{role:"user",content:[{type:"text",source_lang_code:sourceLang,target_lang_code:targetLang,text}]}]`. Its UI uses mixed locale codes, e.g. `en`, `tr_TR`, `de_DE`, `fr_FR`, `zh_TW`, `fil_PH`; these are not the current app's M2M codes or NLLB codes. It reads final assistant `content`, not `translation_text`. — [Translator implementation](https://huggingface.co/spaces/webml-community/TranslateGemma-WebGPU/blob/main/src/ai/Translator.ts), [Language constants](https://huggingface.co/spaces/webml-community/TranslateGemma-WebGPU/blob/main/src/constants.ts).
- NLLB license is **CC-BY-NC-4.0** in both original and Xenova export metadata. Original card says research model, not released for production deployment, not intended for document translation; trained with input lengths at most 512 tokens. License restrictions and intended-use cautions are distinct: noncommercial restriction is a license condition, while the production warning is the model author's stated intended scope. — [Original card](https://huggingface.co/facebook/nllb-200-distilled-600M/blob/main/README.md), [Export metadata](https://huggingface.co/api/models/Xenova/nllb-200-distilled-600M?blobs=true).

### Inferences
- Future design, not implemented here: maintain canonical app language identities plus per-model `supportedLanguages`, model-code/prompt mapping, pipeline task, dtype/device, attribution/license, and output normalizer. Keep browser speech BCP-47 codes separate from all model codes.
- Filter options by model coverage, migrate persisted language/model selections, and handle script-specific choices explicitly. Existing “100 languages” and MIT attribution cannot remain unconditional for every model.
- Cap generation length, detect truncation, chunk long documents conservatively, explicitly dispose replaced pipelines, and consider worker execution for UI responsiveness. Text-generation translators can obey malicious instructions embedded in source text or add commentary, so prompt behavior requires testing rather than assuming deterministic MT semantics.

### Gaps
- No full mapping of the current 100 M2M languages was constructed, and no persisted-settings migration was implemented, because the request is research only.

## 3. What practical hardware/download constraints should shape the recommendation?

### Takeaway
Model-file download size is not peak RAM/VRAM. Favor an opt-in 1.8B quantized WebGPU tier over making a 4B translator the default for all browsers; retain a WASM-compatible fallback.

### Cited Findings
- Existing M2M q8 files: encoder 287,856,370 bytes + merged decoder 344,128,178 = **631,984,548 bytes (~632 MB)**, before tokenizer. NLLB q8 encoder 419,120,483 + merged decoder 475,505,771 = **894,626,254 bytes (~895 MB)**. These are sums of two inference files, not full HF repository size and not RAM measurements. — [M2M file metadata](https://huggingface.co/api/models/Xenova/m2m100_418M?blobs=true), [NLLB file metadata](https://huggingface.co/api/models/Xenova/nllb-200-distilled-600M?blobs=true).
- TranslateGemma text 4B q4 graph plus two data chunks = **3,091,548,551 bytes (~3.09 GB)**; q4f16 total **2,714,995,011 bytes (~2.715 GB)**. The browser demo's own configured total size including support files is 3,111,894,696 bytes. Thus “4B works on mobile/edge” from Google is not evidence that this particular ONNX browser package is comfortable on low-memory phones. — [HF file metadata](https://huggingface.co/api/models/onnx-community/translategemma-text-4b-it-ONNX?blobs=true), [Browser demo size](https://huggingface.co/spaces/webml-community/TranslateGemma-WebGPU/blob/main/src/ai/Translator.ts), [Google positioning](https://blog.google/innovation-and-ai/technology/developers-tools/translategemma/).
- ORT Web documents protobuf's 2 GB limit (use external data), browser ArrayBuffer restrictions, and 4 GB WASM32 linear-memory limit. External data solves protobuf/file packaging, not total device-memory scarcity. Treat this documentation's runtime ceiling as platform guidance, not proof of this installed version's peak memory on every browser. — [ORT Web large models guide](https://onnxruntime.ai/docs/tutorials/web/large-models.html).
- Installed Transformers.js dtype logic defaults WASM to q8 and other unspecified devices to fp32, and includes a WebGPU FP16 support check via adapter feature `shader-f16`. Therefore explicitly request a known available dtype; merely switching device to WebGPU can otherwise trigger unexpectedly large fp32 loading. q4f16 specifically uses FP16 plus block-quantized 4-bit weights. — [Installed dtypes source](file:///home/ray/repo/bir/node_modules/@huggingface/transformers/src/utils/dtypes.js).
- Tencent's MT2 upstream advertises a **440 MB 1.25-bit** edge model, but links it as **GGUF**, alongside 2-bit GGUF and FP8 variants. This is not the same artifact as the verified ~1.075 GB Transformers.js q4f16 ONNX package; do not promise a 440 MB Transformers.js download. — [Upstream MT2 links](https://huggingface.co/tencent/Hy-MT2-1.8B/blob/main/README.md), [JS export files](https://huggingface.co/api/models/konstbet/Hy-MT2-1.8B-ONNX?blobs=true).

### Inferences
- GPU feature detection, available adapter limits, memory/error handling, download consent and storage quota checks are necessary before enabling a large tier. Cache can reduce repeat network downloads but does not eliminate startup memory allocation or GPU compilation.
- Quantized 1.8B is the most plausible quality-upgrade/browser-cost compromise here; 4B is an optional powerful-desktop route. Exact minimum 4/8/16 GB system-RAM or VRAM numbers would be unsupported without measuring specific devices.
- Recommendation to coordinator: do not replace the current default in this research task. Propose a follow-up EN↔TR evaluation of **MT2 1.8B q4f16** (latest, Apache upstream, fresh JS export), **HY-MT1.5 q4** (established onnx-community usage), and **TranslateGemma 4B q4** (proven browser source, large), while flagging **NLLB as noncommercial/research-only option** and preserving M2M fallback.

### Gaps
- No client hardware inventory, actual WebGPU adapter/FP16 query, speed benchmark, peak-memory profile, or multilingual quality test was performed. The Linux coding-agent host's hardware would not establish hardware available to GitHub Pages visitors.
